## 0. 가장 중요한 발견 (실측)

**모델 01·02·03은 거의 전부가 폭 ≈ w(8 mm) 벽이다.**

단면을 반경 r로 opening(buffer(−r)·buffer(+r))해서 잃는 면적 비율을 쟀다(전 층 합).

| 모델 | r=3.9 | r=3.99 | r=3.999 | **r=4.0 (= w/2)** |
|---|---:|---:|---:|---:|
| 01 | 0.006% | 0.006% | 0.478% | **75.9%** |
| 02 | 0.002% | 0.010% | 0.019% | **58.4%** |
| 03 | −9.993%(이상치) | 0.002% | 1.869% | **85.9%** |
| 04·05 | 0 | 0 | 0 | 0 |
| 06 | 0.211% | 0.220% | 0.221% | 0.222% |

- 반경 w/2 − 0.01 mm 원판은 거의 모든 곳에 들어가고, 정확히 w/2 원판은 대부분 못 들어간다 → 벽 두께가 정확히 w다. 층 0 평균 폭 추정치(2A/둘레)도 01 8.29 / 02 7.97 / 03 8.40 mm.
- 결과: C-32 그대로(윤곽 1개 at o = w/2 + 해칭)면 윤곽 오프셋이 벽 중심선으로 **퇴화**한다. 프로토타입에서 L·w/면적 = 01 0.23 / 02 0.23 / 03 0.18 → **01~03 FAIL 예상(가설)**. → 결정 시트 **P2(필수)**.
- 기본값 7("폭 < w")은 판정 반경을 정확히 w/2로 두면 수치적으로 동률이라 불안정하다. 그래서 수치 허용오차 ε_w를 둔다(V10, 자동). ε_w = 0.01 mm면 모든 모델이 0.5% 미만이므로 조건부 항목 P3은 조건 미충족이다.
- 03의 r=3.9 음수값(opening 면적 > 원래 면적)은 R1의 자기접촉 홀 근처에서 생긴 shapely buffer 이상으로 보인다(가설). → 발자국 ⊂ 단면 검사를 테스트에 넣는다(§7).

## 5. 인터페이스 (초안)

```python
TOOLPATH_VERSION = "toolpath-0"

@dataclass(frozen=True, slots=True)
class ToolpathParams:
    s_mm: float          # 기본 w (C-29)
    o_mm: float          # 기본 w/2 (V1=I1 기준, P1 결정 후 확정)
    n_c: int             # 기본 1
    chord_mm: float      # 0.1 (가설값)
    lift_dz_mm: float    # 2h (가설값, 기록만)
    eps_w_mm: float      # 0.01 (V10)
    @classmethod
    def from_config(cls, config) -> "ToolpathParams": ...   # w, h는 config에서

@dataclass(frozen=True, slots=True)
class Pass:
    layer: int
    z: float                                  # tcp_z_reference에 따른 층 z
    kind: Literal["contour", "hole", "hatch", "medial"]   # medial은 P2 = a일 때만
    vertices: tuple[tuple[float, float], ...] # 순서 있는 XY. 닫힌 고리는 첫 점을 끝에 반복
    length: float
    footprint: BaseGeometry                   # Validator와 같은 buffer
    reachable_robots: frozenset[int]

@dataclass(frozen=True, slots=True)
class Toolpath:
    passes: tuple[Pass, ...]                  # (층, 정준 순서) 순
    params: ToolpathParams
    thin_lost_mm2: tuple[float, ...]          # 층별
    empty_reach_count: int

def generate(stack: LayerStack, config, params: ToolpathParams | None = None, *,
             cache_dir=None, use_cache=True) -> Toolpath: ...
class ToolpathError(Exception): code  # WORKSPACE_VIOLATION 등
```
- `config`는 slicing·lower_bound와 같은 덕 타이핑. 숫자는 코드에 넣지 않는다.

## 6. 의사코드 (보고서용, E7)

```
generate(stack, cfg, p):
  for layer k in stack:                       # 층별 독립
    P ← layer.geometry; out ← []
    thin_k ← area(P) − area(open(P, w/2 − ε_w))
    for poly in parts(P):
      for i in 0..n_c−1:                      # 윤곽(바깥·구멍)
        R ← poly ⊖ (o + i·s)   [round join, chord]
        out += rings(R) as contour/hole (orient)
      [P2=a] W ← (poly ⊖ (w/2 − ε_w)) \ (poly ⊖ (w/2)) 근방 → 중심선 그래프 → medial 패스
      H ← poly ⊖ (o + (n_c−1)·s + w/2)        # 해칭 영역
      L ← 각 θ_k(0°/90°) 방향 선들 y_min(H)+s/2+i·s ∩ H
      L ← 이웃 선 끝점 연결(연결선 발자국 ⊂ P일 때만) → 패스
      out += L as hatch
    drop length-0; check workspace (raise); reach set = ∩ robots(all vertices)
    order out: contours first, then nearest-next (start = prev end)
  return Toolpath(...)
```

## 7. 테스트와 합격 기준 (모두 자동 판정)

| # | 테스트 | 합격 기준 |
|---|---|---|
| 1 | 정사각형 100×100 | 발자국 합집합 ⊂ P(overfill 면적 ≤ 1e-6·A), coverage ≥ 0.99(가설값), 0.97 ≤ L·w/A ≤ 1.03(가설값; 프로토타입 04 = 1.0001) |
