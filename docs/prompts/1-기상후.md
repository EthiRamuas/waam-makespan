# 프롬프트 1 — 기상 후 작업 시작

권장: sonnet / medium. 숫자 정리는 `log-summarizer`(haiku)에 맡겨도 된다. **이 프롬프트는 읽기 전용이다.** 파일 수정·커밋을 하지 않는다(pytest 캐시 제외).

먼저 `docs/prompts/_common.md`를 읽고 그 규칙(헤더, 보고 형식, 결정 양식, 금지·중단)을 따른다. 입력 헤더는 이 메시지 맨 위에 있다.

## 1.1 과거 보고 — 어제와 새벽 결과, 선택 대기 사항

읽을 것
- `git log --oneline -15`, `git status --short`
- `PROGRESS.md` 전체, `DECISIONS.md`의 "결정 대기"
- 가장 최근 `nightly/*` 브랜치와 기본 브랜치의 `git diff --stat`
- `pytest -q` (실행해서 확인. 실행하지 못하면 `미측정`)

출력 (이 순서)
1. **간밤 세션**: 계획된 큐 대비 `완료 / 보류 / 미착수` 표. 열: 모듈, 상태, 커밋, pytest, 리뷰 결과.
2. **변경 / 측정 / 판단** 3줄.
3. **중단 또는 이상 징후**: 있으면 원인과 현재 상태, 없으면 `없음`.
4. **시간 기록**: 계획 대비 실제. `PROGRESS.md`에 기록이 없으면 `기록 없음`.
5. **병합 전 확인 목록**: `nightly/*`의 신규 코드는 **병합하지 않는다.** 확인할 것을 체크리스트로 낸다 — 리뷰 통과 / pytest 통과 / 기존 테스트·fixture 변경 없음(`git diff`로 확인) / 신규 코드 diff에서 직접 훑을 지점 3개.

## 1.2 현재 보고 — 전체에서 어디까지 왔고 무엇이 남았나

표 하나: 단계(1~4), 모듈, 상태(완료 / 진행 / 보류 / 미착수), 근거(커밋 또는 테스트). 막힌 곳과 차단 관계를 한 줄로. 다음 작업 후보는 **이름만** 적는다. 제안은 프롬프트 2에서 한다.

## 1.3 ★1 결정 구간 — 선택 사항 제출

`DECISIONS.md`의 "결정 대기"와 간밤에 보류된 항목으로 `_common.md` §4-1의 **B등급 결정 메모**를 만든다.
- 한 구간 최대 3건. 넘치면 데드라인이 임박하거나 다른 결정을 막는 순서로 올리고 나머지는 `다음 구간`으로 표시.
- 설계·알고리즘 방향이 걸린 결정은 `waam-architect`에 근거를 받아 선택지와 권고에 반영한다.
- 마지막 줄에 답 형식을 안내한다: `D-xx=a, D-yy=b, D-zz=보류`

**여기서 멈춘다.** 사용자 답이 오기 전에는 아무것도 변경하거나 시작하지 않는다. 답이 오면 사용자가 프롬프트 2를 보낸다.
