# 프롬프트 3 — 주간 시간대 중간중간 결정

권장: sonnet / medium. 낮 동안 필요할 때마다 반복해서 쓴다 (한 사이클 = 3.1~3.4). **★3 승인 전에는 파일을 수정하지 않는다.**

먼저 `docs/prompts/_common.md`를 읽고 따른다. 입력 헤더는 이 메시지 맨 위에 있다.

> **간이 확인:** 메시지에 `신호만`이라고 적혀 있으면 3.1을 `신호 한 줄(계속 / 개입 필요 / 중단 권고) + 근거 한 줄 + 결정 대기 건수`로 줄이고, 3.2~3.4는 하지 않는다. 읽기 전용이며 새 작업을 시작하지 않는다.

## 3.1 현재 보고 — 전체에서 어디까지 왔고 무엇이 남았나

읽을 것: `git log --oneline -5`, `PROGRESS.md`, `DECISIONS.md`의 "결정 대기" — 이 세 가지만.
출력: **마지막 보고 이후 달라진 것만** + 전체 위치 한 줄. 변경 / 측정 / 판단 3줄. 지금 진행 중인 작업이 있으면 그 단계와 예상 완료 시각(근거 포함, 없으면 `미확인`).

## 3.2 현재 제안 — 지금 하에서 진행 예정인 가능한 작업, 그리고 사용자 개입 정도와 빈도

헤더를 입력으로 아래를 낸다.
1. 이번 사이클에 진행할 작업 (순서, 등급, 완료 기준, 중단 조건, 예상 시간과 근거). 사전 결정이 끝나지 않은 B등급 작업은 올리지 않는다.
2. **열 선택 ①②③ 중 하나**와 사유 (`docs/handoff.md` §7).
3. **개입 정도와 빈도**: 다음 확인까지 __분 / 그 사이 내게 올 결정 예상 __건 (없으면 0) / 내가 자리를 비워도 되는 최대 시간.
4. 결정이 필요한 일이 생기면 어떻게 처리할지: 사전에 정한 B등급 위임 범위에 따라 (a) 되돌릴 수 있으면 기본안으로 진행하고 `DECISIONS.md`에 기록 (b) 아니면 그 작업만 보류하고 의존 없는 다음 작업으로 이동. 위임 범위가 아직 정해지지 않았으면 (b)를 쓴다.

## 3.3 ★3 결정 구간 — 제안 실행 승인

`_common.md` §4-3 양식으로 제출한다. B등급 결정이 있으면 §4-1 메모를 붙인다(합쳐서 최대 3건). 답 형식을 안내하고 **여기서 멈춘다.**

## 3.4 현재 지시 — ★3 답에 따라 실행 시작

- `실행`: `PROGRESS.md`에 시작 시각을 기록하고 시작한다.
- `수정: …`: 고쳐서 ★3을 다시 제출한다.
- `대기`: 아무것도 시작하지 않는다. 다음 호출 때까지 상태를 바꾸지 않는다.
- `열 변경: n`: 해당 열의 기본값으로 3.2를 다시 쓴 뒤 ★3을 다시 제출한다.

실행 규칙은 프롬프트 2의 2.4와 같다 (모듈마다 리뷰 게이트·체크포인트 커밋, 중단 조건 `_common.md` §5, 리뷰 탐색 3분). 사이클이 끝나면 `PROGRESS.md`에 한 줄을 남긴다: 시각, 한 일, 다음 확인 시각.
