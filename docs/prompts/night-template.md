# 야간 세션 {{날짜}} — 사람 없음

이 세션에는 사람이 없다. 질문하지 말고 아래 규칙대로 판단한다. 규칙이 답을 주지 않는 상황이면 해당 작업을 **보류**한다.

## 조건 (사람이 ★4에서 승인한 것)

- 시작 {{시각}} · 종료 한도 {{시각}} · 열 ④ · 작업 브랜치 `nightly/{{날짜}}`
- 모델: 구현 sonnet(medium), 리뷰 게이트 `waam-reviewer`(opus, high), 요약 `log-summarizer`(haiku)
- 먼저 `docs/prompts/_common.md` §3, §5, §6을 읽고 따른다.

## 시작 절차

1. `git status --short`가 비어 있는지 확인한다. 비어 있지 않으면 **아무것도 하지 말고** `PROGRESS.md`에 이유를 적고 종료한다.
2. `nightly/{{날짜}}` 브랜치로 전환한다(없으면 생성). 기본 브랜치에는 커밋하지 않는다.
3. `pytest -q`를 실행해 시작 상태를 `PROGRESS.md`에 기록한다. 이미 실패 중이면 큐를 시작하지 않고 종료한다.

## 큐 (순서 고정, 바꾸지 않는다)

(항목마다 아래 형식으로 채운다)
- **Q{{n}}. {{모듈}}**
  - 명세: {{파일·절}} / 인터페이스: {{시그니처}} / 테스트 케이스: {{목록}}
  - 완료 기준: {{pytest 통과 수 · 건전성 테스트 · Validator exit code 등 자동 판정 기준}}
  - 중단 조건: 공통 규칙 + {{항목별}}
  - 의존: {{없음 | Qn}}
  - 예상 시간: {{값}} ({{실측|가설}})
- **여유분 R1 (읽기 전용).** {{로그 요약 | 문서 갱신}}

## 항목별 흐름

구현 → pytest → `waam-reviewer`(탐색 3분 이내, 샘플 수 상한) → 지적 반영 → pytest → 체크포인트 커밋 → 다음 항목.
리뷰를 건너뛰지 않는다. 리뷰가 끝나기 전에 다음 항목으로 넘어가지 않는다.

## 규칙

- **명세에 없는 결정을 만나면** 그 항목을 보류한다. `DECISIONS.md`에 B등급 메모를 `상태: 보류`로 남기고(`_common.md` §4-1 필드), **의존하지 않는** 다음 항목만 계속한다. 앞 항목이 막히면 그에 의존하는 항목은 모두 보류한다.
- 기존 테스트와 골든 fixture를 수정하지 않는다. 신규 테스트 추가만 한다. 통과시키려고 기대값을 바꾸지 않는다.
- 특정 `tests/NN`에 맞춘 하드코딩을 하지 않는다.
- 설계를 바꾸지 않는다. 명세에 적힌 인터페이스와 다르게 구현해야 하면 보류한다.
- push, 삭제, 교수님 레포·`config.yaml`·`target.stl`·`docs/experiments.md` 수정은 어떤 이유로도 하지 않는다.

## 중단 조건

다음 중 하나라도 일어나면 현재 항목을 멈추고, 상태를 커밋하고, `PROGRESS.md`에 원인과 현재 상태를 쓴다. 1~3번은 의존 없는 항목이 남아 있어도 **세션 전체를 종료**하고, 4~5번은 해당 항목만 보류하고 의존 없는 다음 항목을 계속한다.
1. 같은 오류로 2회 연속 실패 *(세션 종료)*
2. 리뷰 반영 후 pytest 실패 *(세션 종료)*
3. 종료 한도 시각 도달 또는 항목별 타임박스({{값}}) 2배 초과 *(세션 종료)*
4. 명세 밖 결정 필요 *(해당 항목만 보류)*
5. 금지 행위가 필요해 보임 *(해당 항목 보류)*
6. 토큰 95% — 측정 방법: {{확인된 방법 | 미확인이면 이 조건은 적용하지 않고 체크포인트 커밋 간격을 줄인다}}

## 기록 (바로바로)

- 항목 시작·종료 시각을 `PROGRESS.md`에 즉시 기록한다.
- 체크포인트마다 `PROGRESS.md`를 갱신한다: 현재 항목, 통과 테스트 수, 막힌 곳, 다음 항목, 신호 한 줄.

## 종료 절차와 아침 보고

1. 마지막 항목이 끝났거나 중단 조건에 걸렸으면 `pytest -q`를 한 번 더 실행한다.
2. `PROGRESS.md`의 "야간 결과" 절에 쓴다: 큐 대비 `완료 / 보류 / 미착수` 표, **변경 / 측정 / 판단** 3줄(측정하지 않은 값은 `미측정`), 리뷰 지적의 반영·미반영 목록과 이유, 단계별 실제 소요 시간, 신규 코드 diff에서 사람이 직접 볼 지점 3개.
3. `DECISIONS.md`에 보류된 결정이 모두 `대기`로 남아 있는지 확인한다.
4. 종료한다. 병합하지 않는다.

## 복귀 체크리스트 (사람이 아침에 한다 — 프롬프트 1이 같은 순서로 보고한다)

1. `git log --oneline -10` — 커밋이 순서대로 쌓였는가
2. `PROGRESS.md`의 "야간 결과" — 신호 한 줄과 3줄 보고
3. pytest·건전성 결과 — 실패나 `미측정`이 있는가
4. 기존 테스트·fixture가 바뀌지 않았는가 (`git diff --stat`)
5. `DECISIONS.md`의 결정 대기 목록
6. 신규 코드 diff를 직접 훑은 뒤에만 병합한다
